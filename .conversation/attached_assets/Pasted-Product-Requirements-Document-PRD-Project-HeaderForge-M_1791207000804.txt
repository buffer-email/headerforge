Product Requirements Document (PRD)Project: HeaderForge (ModHeader Clone Chrome Extension)Document Status: Draft / Ready for ReviewTarget Platform: Chromium-based Browsers (Chrome, Edge, Brave, Arc, Opera)Manifest Version: Chrome Extension Manifest V3 (MV3)Document Version: 1.0.01. Executive Summary & Product Vision1.1 Problem StatementWeb developers, QA testers, and security researchers routinely need to modify HTTP request and response headers (such as Authorization, Cookie, X-Forwarded-For, and custom headers) to test APIs, staging environments, bypass geo-restrictions, or simulate varied client contexts. While existing extensions like ModHeader are popular, many users seek a lightweight, privacy-focused, open-source alternative that does not collect telemetry, fully supports modern Chrome Manifest V3 performance constraints, and provides seamless import/export workflows.1.2 Product VisionHeaderForge is an open-source, developer-first Chromium extension that enables seamless, granular manipulation of HTTP request and response headers, URL redirects, and query parameters. It focuses on local-first data storage, instant execution via Chrome’s declarativeNetRequest API, and profile-based sharing.2. Core Features & Functional Requirements3.1 Header Management Engine (Core)Request Header Modification:Ability to Append, Set (Overwrite), or Remove HTTP request headers.Support for standard headers (Authorization, User-Agent, Referer, Origin, etc.) and arbitrary X-* custom headers.Response Header Modification:Ability to Append, Set, or Remove response headers (crucial for CORS troubleshooting such as overriding Access-Control-Allow-Origin).Granular Enablement Toggles:Global Master Switch: Instant kill switch in the popup to pause all modifications without losing state.Rule-Level Toggle: Checkbox next to each individual header row to enable/disable without deleting.Profile-Level Toggle: Activate or pause entire profiles independently.Dynamic Tokens & Functions:Support for template variables in values:{{$timestamp}} (Unix timestamp){{$isoDate}} (ISO 8601 string){{$uuid}} (Random v4 UUID){{$randomInt(min, max)}}3.2 URL Scoping & FilteringUsers must not accidentally broadcast test headers to unintended domains (e.g., banking or personal accounts).URL Pattern Matching:Glob/Wildcard support: https://*.staging.example.com/*Regular Expression (RegEx) filter support.Resource Type Filtering:Ability to filter rule execution by resource type: main_frame, sub_frame, xmlhttprequest / fetch, script, stylesheet, image, etc.Tab Scope Modes:Global Mode: Applies to all matching tabs across all browser windows.Current Tab Only: Applies rules strictly to the active tab ID.3.3 Profiles & PresetsMulti-Profile Management: Create multiple isolated profiles (e.g., "Staging Admin Auth", "Local Testing", "CORS Bypass", "Mobile User-Agent").Profile Operations: Create, duplicate, rename, reorder, and delete profiles.Multiple Active Profiles: Allow users to toggle multiple profiles simultaneously (rules cascade with explicit priority ordering).3.4 Import & Export WorkflowsJSON File Export:Export single active profile or complete configuration (all profiles, settings, and filters) as .json.JSON Import:Import from .json file with merge or overwrite conflict resolution options.Clipboard & Quick Sharing:"Copy as cURL" or "Copy Profile JSON to Clipboard"."Paste from Clipboard" for rapid one-click team sharing.ModHeader Legacy Schema Compatibility:Auto-detect and migrate configuration files exported from the original ModHeader extension.3.5 Extension Icon & Visual FeedbackDynamic Badge:Numeric badge on the extension action icon indicating the number of currently active headers (e.g., 3).Visual color badge state: Green (active modifications), Gray (disabled/idle), Red/Amber (error or collision).4. Technical Architecture (Manifest V3)4.1 Chrome APIs & Implementation StrategyChrome Manifest V3 restricts background pages and deprecates blocking chrome.webRequest. HeaderForge will leverage chrome.declarativeNetRequest (DNR).+-------------------------------------------------------------------+

DeclarativeNetRequest Rule CompilationWhen a user updates a header in the UI:The UI writes state to chrome.storage.local.The Service Worker receives an onChanged event or direct message.The Service Worker converts active headers into chrome.declarativeNetRequest.Rule objects:Action type: modifyHeadersrequestHeaders: array of { header: string, operation: 'set' | 'append' | 'remove', value?: string }responseHeaders: array of modification objects.condition: { urlFilter: '...', resourceTypes: [...] }Calls chrome.declarativeNetRequest.updateDynamicRules with removeRuleIds and addRules.4.2 Storage Schemainterface HeaderRule {
  id: string;
  enabled: boolean;
  type: 'request' | 'response';
  operation: 'set' | 'append' | 'remove';
  name: string;
  value: string;
}

interface FilterCondition {
  urlPattern: string; // e.g. "https://api.dev.local/*"
  isRegex: boolean;
  resourceTypes: chrome.declarativeNetRequest.ResourceType[];
}

interface Profile {
  id: string;
  name: string;
  colorTag?: string;
  enabled: boolean;
  headers: HeaderRule[];
  filters: FilterCondition[];
}

interface AppStorage {
  version: string;
  masterEnabled: boolean;
  activeProfileIds: string[];
  profiles: Profile[];
  settings: {
    theme: 'system' | 'dark' | 'light';
    showBadgeCount: boolean;
    tabScopeDefault: 'global' | 'tab';
  };
}

Non-Functional & Security Requirements6.1 PerformanceNetwork Overhead: $0 \text{ ms}$ user-space latency. Since DNR rules are evaluated natively by Chromium's C++ network stack, requests are modified in-engine without background script round-trips.Popup Launch: Cold launch time of the popup must stay under $120 \text{ ms}$.6.2 Privacy & SecurityZero Remote Telemetry: No external network requests to external analytics, tracking pixels, or third-party servers.Sensitive Data Protection: Auth tokens and cookie values remain strictly inside local browser storage (chrome.storage.local).Minimal Permissions:declarativeNetRequestdeclarativeNetRequestWithHostAccess or <all_urls>storagetabs (optional, only needed for tab-specific scoping mode)7.
